# Authoring Tauri 2 plugins

A Tauri plugin is a Cargo crate (usually `tauri-plugin-<name>`) plus an optional npm package, permissions, and optional Android/iOS native libraries. Plugins can add commands, manage state, hook the app lifecycle, and expose Rust APIs.

Official docs: <https://v2.tauri.app/develop/plugins/> and <https://v2.tauri.app/develop/plugins/develop-mobile/>.

## Scaffold

```sh
npx @tauri-apps/cli plugin new my-plugin
# or
cargo tauri plugin new my-plugin
```

Flags:

- `--no-api` — Rust-only plugin, no npm package.
- `--android` — add an Android library project.
- `--ios` — add a Swift package.
- `plugin android init` / `plugin ios init` — add mobile support to an existing plugin.

The generated crate is `tauri-plugin-my-plugin`; the plugin name registered with the builder is `my-plugin`.

## Project layout

```text
tauri-plugin-my-plugin/
├── src/
│   ├── commands.rs      # commands exposed to the WebView
│   ├── desktop.rs       # desktop implementation
│   ├── mobile.rs        # mobile implementation
│   ├── error.rs
│   ├── lib.rs           # builder, state, exports
│   └── models.rs
├── permissions/
│   ├── default.toml
│   └── autogenerated/   # generated from COMMANDS in build.rs
├── android/             # Kotlin library (optional)
├── ios/                 # Swift package (optional)
├── guest-js/            # TypeScript bindings (optional)
├── dist-js/             # transpiled JS
├── build.rs
├── Cargo.toml
└── package.json
```

`desktop.rs` and `mobile.rs` implement the same API shape; `lib.rs` re-exports the right one with `#[cfg(desktop)]` / `#[cfg(mobile)]`.

## Naming and identifiers

- Crate: `tauri-plugin-<name>`.
- npm: `tauri-plugin-<name>-api`, or preferably `@scope/plugin-<name>`.
- Plugin name and permission identifiers: lowercase ASCII letters, digits, and hyphens. No underscores, no uppercase, no leading/trailing hyphen. A single colon is allowed for `<plugin>:<permission>`.
- Base name limit is 64 characters; the full identifier is limited to 129.

Invalid names fail the build with `identifiers can only include lowercase ASCII, hyphens which are not leading or trailing, and a single colon if using a prefix`.

## Plugin builder

```rust
use tauri::{
    plugin::{Builder, TauriPlugin},
    Runtime,
};

pub fn init<R: Runtime>() -> TauriPlugin<R> {
    Builder::new("my-plugin")
        .invoke_handler(tauri::generate_handler![commands::ping])
        .setup(|app, api| {
            app.manage(MyState::default());
            Ok(())
        })
        .build()
}
```

With configuration:

```rust
#[derive(serde::Deserialize)]
pub struct Config {
    pub timeout: usize,
}

pub fn init<R: Runtime>() -> TauriPlugin<R, Config> {
    Builder::<R, Config>::new("my-plugin")
        .setup(|app, api| {
            let timeout = api.config().timeout;
            Ok(())
        })
        .build()
}
```

Use `Builder::<R, Option<Config>>` if the config is optional. The plugin config comes from `tauri.conf.json > plugins > my-plugin`.

Expose a Rust API by managing a handle and adding an extension trait:

```rust
pub trait MyPluginExt<R: Runtime> {
    fn my_plugin(&self) -> &MyPlugin<R>;
}

impl<R: Runtime, T: tauri::Manager<R>> MyPluginExt<R> for T {
    fn my_plugin(&self) -> &MyPlugin<R> {
        self.state::<MyPlugin<R>>().inner()
    }
}
```

Consumers then call `app.my_plugin()`.

## Configuration

In the consuming app:

```json
{
  "plugins": {
    "my-plugin": {
      "timeout": 30
    }
  }
}
```

Plugins should reject unknown fields and document defaults. Keep the config struct `serde::Deserialize` and avoid `unwrap()` on optional user input.

## Lifecycle hooks

| Hook | When | Use |
| --- | --- | --- |
| `setup` | Plugin initialized | Register state, spawn tasks, initialize mobile code. |
| `on_navigation` | WebView attempts navigation | Return `false` to cancel. |
| `on_webview_ready` | New window created | Inject initialization scripts, attach listeners. |
| `on_event` | Event loop event | Handle `RunEvent`, cleanup on exit. |
| `on_drop` | Plugin dropped | Release resources. |

```rust
Builder::new("my-plugin")
    .on_navigation(|_window, url| url.scheme() != "forbidden")
    .on_webview_ready(|window| {
        window.listen("content-loaded", |_event| {});
    })
    .on_event(|app, event| {
        if let tauri::RunEvent::Exit = event {
            // cleanup
        }
    })
    .build()
```

## Commands and JS bindings

```rust
// src/commands.rs
use tauri::{command, ipc::Channel, AppHandle, Runtime};

#[command]
pub async fn upload<R: Runtime>(
    app: AppHandle<R>,
    url: String,
    on_progress: Channel<u32>,
) -> crate::Result<()> {
    on_progress.send(50).unwrap();
    Ok(())
}
```

Register it:

```rust
Builder::new("my-plugin")
    .invoke_handler(tauri::generate_handler![commands::upload])
```

From JavaScript, the command name is prefixed with the plugin name:

```ts
import { invoke, Channel } from '@tauri-apps/api/core';

const onProgress = new Channel<number>();
await invoke('plugin:my-plugin|upload', { url, onProgress });
```

Generate a typed wrapper in `guest-js/index.ts`:

```ts
export async function upload(url: string, onProgress: (n: number) => void) {
  const channel = new Channel<number>();
  channel.onmessage = onProgress;
  await invoke('plugin:my-plugin|upload', { url, onProgress: channel });
}
```

Commands are denied by default; add permissions before expecting them to work.

## Permissions

Put the command list in `build.rs`:

```rust
const COMMANDS: &[&str] = &["ping", "upload"];

fn main() {
    tauri_plugin::Builder::new(COMMANDS).build();
}
```

This generates `allow-ping` / `deny-ping` and `allow-upload` / `deny-upload` permissions under `permissions/autogenerated/`.

Define a default set:

```toml
# permissions/default.toml
"$schema" = "schemas/schema.json"

[default]
description = "Default permissions for my plugin"
permissions = ["allow-ping"]
```

Group permissions:

```toml
[[set]]
identifier = "upload-files"
description = "Allows uploading files"
permissions = ["allow-upload"]
```

Consumers reference them in a capability:

```json
{ "permissions": ["my-plugin:default"] }
```

The default is added automatically when the consumer installs the plugin with `tauri add my-plugin`. Never rely on that alone; check the capability.

## Scopes

A permission can carry a global scope, and consumers can attach a command-specific scope:

```toml
[[permission]]
identifier = "allow-spawn-node"
description = "Allows spawning the node binary"

[[permission.scope.allow]]
binary = "node"
```

Define the scope type with `schemars::JsonSchema` so consumers get autocomplete:

```rust
#[derive(Debug, schemars::JsonSchema)]
pub struct Entry {
    pub binary: String,
}
```

Generate the schema in `build.rs`:

```rust
#[path = "src/scope.rs"]
mod scope;

fn main() {
    tauri_plugin::Builder::new(COMMANDS)
        .global_scope_schema(schemars::schema_for!(scope::Entry))
        .build();
}
```

Read scopes in a command and enforce **both** global and command scopes:

```rust
use tauri::ipc::{CommandScope, GlobalScope};

#[command]
async fn spawn(
    command_scope: CommandScope<'_, Entry>,
    global_scope: GlobalScope<'_, Entry>,
) -> crate::Result<()> {
    let allowed = command_scope.allows();
    let denied = command_scope.denies();
    // Validate against both; deny wins.
    Ok(())
}
```

A permission without commands is a global scope permission. A plugin that accepts arbitrary paths or binaries must reject anything outside the scope; capabilities only grant the command, not the validation.

## Mobile plugins

The template includes an Android Kotlin library and/or an iOS Swift package. Rust calls native code through `PluginHandle::run_mobile_plugin`.

### Android

```kotlin
@TauriPlugin(
    permissions = [
        Permission(strings = [Manifest.permission.POST_NOTIFICATIONS], alias = "postNotification")
    ]
)
class MyPlugin(private val activity: Activity) : Plugin(activity) {
    @Command
    fun openCamera(invoke: Invoke) {
        val args = invoke.parseArgs(OpenArgs::class.java)
        val result = JSObject()
        result.put("path", "/path/to/photo.jpg")
        invoke.resolve(result)
    }
}
```

- `@InvokeArg` marks argument classes; inner objects need it too.
- Required: `lateinit var name: String`; optional: `var timeout: Int? = null`; default: `var quality: Int = 100`.
- Native commands run on the main thread. Move blocking I/O to `CoroutineScope(Dispatchers.IO).launch { ... }`.
- Lifecycle: `load(webView)` and `onNewIntent(intent)`.

### iOS

```swift
class MyPlugin: Plugin {
    @objc public func openCamera(_ invoke: Invoke) throws {
        let args = try invoke.parseArgs(OpenArgs.self)
        invoke.resolve(["path": "/path/to/photo.jpg"])
    }
}
```

- Argument classes inherit `Decodable`; inner objects do too.
- Required: `let name: String`; optional: `var timeout: Int?`. Swift does not support default values here; use `nil` and default inside the method.
- Lifecycle: `load(webview:)`.

### Calling native from Rust

```rust
use tauri::Runtime;

impl<R: Runtime> MyPlugin<R> {
    pub fn open_camera(&self, payload: CameraRequest) -> crate::Result<Photo> {
        self.0
            .run_mobile_plugin("openCamera", payload)
            .map_err(Into::into)
    }
}
```

### Native permissions

Tauri generates `checkPermissions` and `requestPermissions` commands:

```ts
const state = await invoke('plugin:my-plugin|checkPermissions');
if (state.postNotification.startsWith('prompt')) {
  await invoke('plugin:my-plugin|requestPermissions', {
    permissions: ['postNotification'],
  });
}
```

Android declares permissions in `@TauriPlugin(permissions = [...])`; iOS overrides `checkPermissions` and `requestPermissions`.

### Calling Rust from native code

- Android: use JNI. Add `jni = "0.21"` under `[target.'cfg(target_os = "android")'.dependencies]`, `System.loadLibrary(...)`, and expose `Java_<package>_<class>_<method>` functions.
- iOS: use C FFI with `@_silgen_name` on the Swift side and `#[no_mangle] extern "C"` functions in Rust.

Keep the FFI surface small and free any returned C strings.

### Android 16 KB pages

Google Play requires 16 KB page alignment for new submissions. NDK 28+ handles it; if you use an older NDK, add:

```toml
[target.aarch64-linux-android]
rustflags = ["-C", "link-arg=-Wl,-z,max-page-size=16384"]
```

## Events

Emit from native code with `trigger`:

```kotlin
trigger("camera", JSObject().apply { put("open", true) })
```

```swift
trigger("camera", data: ["open": true])
```

Listen from JavaScript with `addPluginListener`, and grant the plugin's permission:

```ts
import { addPluginListener } from '@tauri-apps/api/core';

const listener = await addPluginListener('my-plugin', 'camera', (payload) => {
  console.log(payload);
});
```

```json
{ "permissions": ["my-plugin:default"] }
```

## Testing and publishing

- Test with the generated `examples/tauri-app`; run `cargo build` and `pnpm build` before testing the JS package.
- Add Rust unit tests for scope validation and argument parsing; those are the security-critical parts.
- Declare platform support in `Cargo.toml` so the catalog can render it:

```toml
[package.metadata.platforms.support]
windows = { level = "full" }
linux = { level = "full" }
macos = { level = "full" }
android = { level = "partial", notes = "Restricted to the app folder" }
ios = { level = "none" }
```

- Version the Rust crate and npm package together; document the permission identifiers and scopes.
- Publish the crate to crates.io and the npm package under a scope; do not publish a plugin that silently bundles unrelated code.

## Pitfalls

| Problem | Cause | Fix |
| --- | --- | --- |
| Build fails on identifier | Uppercase or underscore in plugin/permission name | Use lowercase letters, digits, hyphens, one colon. |
| Command denied | Permission not generated or not granted | Add command to `COMMANDS`; add permission to capability. |
| JS call cannot find command | Wrong prefix | Use `plugin:<name>|<command>`. |
| Mobile command never resolves | Native command did not call `invoke.resolve` / `reject` | Resolve or reject on every path. |
| Android ANR | Blocking work on the main thread | Use `Dispatchers.IO`. |
| Scope bypass | Only one of global/command scope checked | Check both; deny wins. |
| npm package out of date | Forgot `pnpm build` in `guest-js` | Rebuild before testing. |
